# 要素式格式转换（传统文书 → 要素式示范文本）

把用户已有的传统式法律文书转换为人民法院推广的**要素式示范文本**格式。这是纯格式转换工作：只做结构重组与要素搬运，不是改写文书，更不是重新起草。

## 任务边界

只做**传统文书 → 要素式示范文本的格式转换 + 要素来源标注**。不做：从零起草文书（用诉讼文书套件 litigation-drafting）、实体法律分析、判决结果预判、格式转换之外的文书润色。

## 硬不变量（常驻，任何任务规模都生效）

1. **事实保真**：转换 MUST NOT 改写、增删或润色原文的事实表述（当事人、金额、日期、诉求措辞）。只允许：结构重组、要素搬运、示范文本要求的固定栏目措辞。
2. **示范文本来源唯一**：模板底稿只能来自本套件 `references/elementized-templates/` 的官方提取文本或官方 PDF 页码引用（最高院 67 类示范文本）。**禁止自拟模板冒充示范文本**。
3. **防编造**：案由、法条号、效力状态必须来自工具实际返回；原文没有的要素不编造。
4. **逐要素来源标注**：每个要素标注三类来源之一——`[取自原文]` / `[原文缺失，需补充]` / `[需用户确认]`。
5. **免责声明**：正式交付必附（见文末模板）。

## 转换流程（五步）

### 第 1 步：输入确认与案由识别

读入用户提供的传统式文书全文（粘贴文本或随附文件内容）。识别案由：

- 依据原文的标题、诉讼请求、事实与理由段的关键要素组合判断（如"借条/利息/归还借款"→民间借贷纠纷）。
- 识别置信度不足（多个候选案由、文书类型不明、内容残缺）→ **中止转换**，列出需要用户澄清的信息，不输出猜测的要素式文书。
- 案由可识别时向用户复述一句："识别为〈案由〉的〈文书类型〉，将转换为对应示范文本格式。"

### 第 2 步：模板匹配与范围诚实

在已收录清单（`references/elementized-templates/CATALOG.md`）中查找对应示范文本：

- **已收录**：加载对应 `.txt` 模板底稿，进入第 3 步。
- **未收录但官方 PDF 内有**（67 类全集见 CATALOG）：如实说明"该案由示范文本已收录在官方 PDF 第 X 页，尚未提取为本地底稿"，给出两个选项——用户确认后按页码提取再转换，或声明本轮无法转换。**不得**用自拟模板顶替。
- **官方 67 类之外**：明示"该案由不在最高院示范文本收录范围"，列出已收录可选项，本轮不转换。

### 第 3 步：要素提取与填充

逐项过示范文本的全部要素，从原文提取对应内容：

- **能提取**：填入原文表述（逐字搬运，不改写），标 `[取自原文]`。
- **原文没有**：栏目保留空白或"无"，标 `[原文缺失，需补充]`——**不编造**。
- **原文表述与栏目要求有出入**（如原文写"被告李四"而栏目要求自然人/法人分列）：保留原文事实，标 `[需用户确认]` 并注明与栏目结构的差异，由用户决定拆分方式。
- 勾选项（□）按原文事实勾选；无法从原文判断的不勾选并标注。

### 第 4 步：法条引用核验（如原文含法律依据）

原文引用了法条的，按接线契约处理：

- 首选 `mcp__fd-legal-search-mcp__law_reference`（条级解析）或 `mcp__fd-find-data-business-mcp__law_search`（效力状态）核验条号与效力；`status` 非"有效"的版本标注"原文引用的该版本已非现行有效"，**不替换、不改写**——保留原文引用并在来源标注中提示。
- 数据源未连接：按 `legal-skill-presets` 诚实降级契约标注 `[模型知识-未验证]`，并在 ⚠️审查备注披露一次。
- 原文没有法律依据的：**不代为新增**（转换不是审查），可在备注提示"示范文本不含法条栏，原诉状亦未引用法条"。

### 第 5 步：交付（要素式文书 + 来源标注表 + 免责声明）

交付物三部分：

1. **要素式文书正文**：按示范文本结构完整填充（含当事人信息、诉讼请求要素表、事实与理由要素栏等），可复制使用。
2. **要素来源标注表**：

| 要素 | 填充内容 | 来源标注 |
|---|---|---|
| 原告姓名 | 张三 | [取自原文] |
| 借款金额 | 50,000 元 | [取自原文] |
| 被告身份证号 | — | [原文缺失，需补充] |
| 利率主张 | 按借条约定 | [需用户确认]（原文未写明具体数值） |

3. **免责声明**（必附）：

> 本文件由 AI 辅助转换生成，仅供参考，不构成法律意见。转换仅做结构重组与要素搬运，未改写原文事实表述；标注 `[原文缺失，需补充]` 的要素请补齐后再提交法院。诉讼有时效限制，如有重大争议，建议咨询执业律师。

## 降级路径

| 情形 | 处置 |
|---|---|
| 输入非传统文书（已是要素式、或不是法律文书） | 如实说明，不转换；已是要素式的可核对与最新示范文本的结构差异（仅提示，不改写） |
| 案由不可识别 | 中止，列澄清清单，不输出猜测文书 |
| 示范文本未提取 | 如实说明 + 提供提取选项，不自拟模板 |
| 文书内容残缺（如缺诉讼请求段） | 已识别部分正常转换，残缺部分标注缺失；不补写 |
| 法条核验数据源未连接 | `[模型知识-未验证]` 标注 + 备注披露一次 |

## 与套件其他技能的分工

- 从零起草起诉状/答辩状 → `litigation-drafting`（生成场景）。
- 已有文书 + "帮我看看有没有问题" → 合同审查/案件分析类技能（审查场景）。
- 已有文书 + "转成法院那种表格式" → **本技能**（转换场景）。

# agent-graph-gate

把 agent 协作当成一张显式的图来检查，而不是写在 prompt 散文里。

图上的东西：**节点**=一个角色/步骤（说明它的输入端口、输出端口、副作用、是否幂等、检查点策略、成本），**边**=依赖与传递了哪些输出。检查器不执行任何节点，只判形状。

## 什么时候用

- 准备把一件工作拆给多个 agent，想知道「拆多少路是形状上撑得住的」。
- 并行跑完发现合并出来的结果丢了信息，想知道丢在哪。
- 想知道某个副作用（写文件、调外部、花钱）有没有被声明和守卫。

## 两个判据，别混

```
width      = 一步最多能同时跑几个节点     → 容量上限，超了就是塞不进
ceiling    = 总工作量 / 关键路径          → 渐进加速上限，超了只是不划算
```

一张 12 路的图可以 width 12 但 ceiling 只有 3.75：**12 个能同时跑，只是不会快 12 倍**，因为串行的头尾封顶。把 ceiling 当成并发上限是常见误读。

## 做法

1. **写图**：一个 YAML，节点声明 `kind / effects / idempotent / checkpoint / cost / inputs / outputs`，边声明 `carries`。
2. **标约束**：把「必须活到合并点的判断」标成 `constraint: true`（例如谁负责哪些文件、按哪条口径）。不标，检查器就分不清「可丢的中间结果」和「不可丢的约束」。
3. **跑检查**：`check` 出全部问题（退出码 0/1/2），`metrics` 出宽度与加速上限，`may-dispatch --concurrency N` 回答这个并发数能不能派。
4. **改合并点**：让合并节点显式消费每条分支的约束。**这是最容易漏、代价最大的一处**——收敛节点不消费某个分支的约束，就等于把那条分支的判断从所有下游决定里抹掉。

## 五个最高频的违规

（完整码表请跑 `fd-agent-graph codes`——它输出的是机器可读全表；本节只列最常见的五个，不出现某个码不代表工具不查它。）

| 违规 | 含义 | 修法 |
|---|---|---|
| `graph.topology.constraint-dropped` | 合并点没消费某分支的约束 | 给合并节点加同名输入并在边上 carry |
| `graph.node.missing-idempotency` | 有 write 以上副作用却没声明幂等 | 补 `idempotent` |
| `graph.retry.non-idempotent` | 检查点在节点边界 + 非幂等 + 有副作用 → 重试会重复副作用 | 改幂等，或换检查点策略 |
| `graph.effect.money-unguarded` | 花钱节点在无审批守卫的路径上 | 路径上插一个 `kind: approve` |
| `graph.topology.unbounded-cycle` | 环上没有节点带 `bound` | 给环上任一节点加 `bound: N` |

## 三条容易踩的

- **各族上限是形状界，不是实测吞吐。** 报告字段叫 `ceiling`，永远要和线性基线同口径比，别当性能承诺。
- **占位符必须被拒绝。** 从任务清单自动生成骨架时，凡是只有人能回答的（副作用、幂等、哪些输出是约束）都留成必被拒的占位符——**让门在猜测上通过，比没有门更坏**。
- **并行不是免费。** 多 agent 会成倍放 token；而收敛节点丢掉少数分支的约束是结构性风险，链式结构里不存在这个问题。宁可少而深，不要多而浅。

## 输出怎么读

每条违规都带 `code / severity / location / fix`，`fix` 说明具体该改什么。`error` 阻断，`warning` 只报告。退出码 `0` 干净、`1` 有 error、`2` 图压根读不了——后两者分开是为了不让 CI 把人引去改图而不是修路径。
